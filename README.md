# 本地资源管理器 <sub>v1.6.1</sub>

基于 PyQt6 的 Windows 本地资源管理工具，采用多模块架构。通过主启动器统一入口，按模块分类管理各类本地资源。

[GitHub 仓库](https://github.com/weizhigao21/Local-File-Explorer)

目前已实现 **写真** 模块和 **音频** 模块，其余模块框架预留。

## 功能

### 主启动器
- **模块入口** - 卡片式启动界面，集中管理所有功能模块
- **模块切换** - 点击模块卡片自动隐藏启动器，关闭模块窗口自动恢复
- **窗口复用** - 再次点击已打开模块可激活已有窗口
- **UI 缩放** - 顶部下拉框选择全局缩放比例（50% ~ 200%），重启后生效，所有模块统一适用

### 写真模块
- **自动扫描** - 递归扫描 `E:\hhh\写真` 目录，识别 `作者/作品/图片` 三级结构
- **目录级指纹** - (2026-08-03) 扫描预检改用目录级指纹，只 stat 目录 mtime，unchanged 判断从全量文件 stat 降为目录 stat
- **增量扫描** - 基于 mtime 对比，仅同步变化的图片/作品/作者，避免全量重建数据库
- **自动扫描收尾** - 进入模块后自动检查目录；若没有变化，立即收起圆环状态，不弹出扫描结果对话框
- **自然排序** - 图片按数字顺序排列（1, 2, 10 而非 1, 10, 2），符合阅读习惯
- **作者筛选** - 左侧作者列表快速切换，支持"全部作者"视图
- **作品搜索** - 按作品名称关键词搜索
- **缩略图墙** - 进入作品后显示所有图片的缩略图网格，自适应布局，懒加载提升性能
- **全屏查看器** - 点击图片进入全屏模式，支持键盘翻页（←/→）、滚轮翻页、ESC 退出
- **进度扫描** - 底部非模态状态条实时显示扫描进度，扫描期间可正常使用程序
- **GPU 加速** - 支持 GPU 友好的像素格式解码，可在设置中开关
- **键盘快捷键** - 全屏切换、搜索聚焦、扫描、刷新、返回等
- **3D 黏土风主题** - 暖米色基底 + 浅橙主色调 + 青蓝强调色，轻拟物新拟态视觉风格

### 音频模块
- **多根目录** - (2026-08-06) 支持同时配置多个音频根目录（设置中可添加/移除），扫描到的歌单直接混合显示在同一个歌单列表中
- **自动扫描** - 递归扫描各音频根目录；主列表显示根级歌单分组，分组内按含音频的文件夹生成子歌单
- **层级结构** - 子歌单在所属主歌单内平铺，名称用 ` > ` 表示完整相对路径；无音频的中间文件夹只保留在路径名称中
- **长路径显示** - 宽度足够时显示完整路径；不足时将上级目录缩为前四个字符，进一步收窄时优先显示末级文件夹名称。悬停查看完整路径，曲目数量保持可见
- **嵌套查询优化** - (2026-07-29) 后代歌单/曲目/封面查询改为递归CTE，一次性替代逐层N+1递归
- **曲目数口径** - 主歌单卡片显示自身与后代的曲目总数；子歌单只显示该文件夹的直接曲目数，同一子歌单不会重复出现
- **主歌单详情** - 主歌单无直接音频时只显示子歌单；同时有音频和子歌单时，两者都显示且分别计数
- **曲目表格** - (2026-08-29) 曲目列表改为表格视图：序号 / 标题 / 类型 / 时长四列，类似文件管理器
- **文件类型** - (2026-08-29) 曲目行显示文件格式（MP3/FLAC/WAV 等，取自扩展名），并支持按类型筛选
- **音频时长** - (2026-08-29) 纯 Python 解析 WAV/FLAC/MP3/M4A/AAC/OGG/WMA 时长，后台线程并行探测、逐行回填，无需额外依赖
- **设备切换跟随** - (2026-08-29) 系统切换默认播放设备（拔插耳机等）时自动重绑音频输出，播放不中断，修复切换后无声
- **歌单卡片** - 网格 / 列表双视图切换，显示封面、名称、曲目数量
- **翻页性能** - 批量查询子歌单数量、按需渲染当前视图；封面按卡片尺寸解码并缓存，在首次绘制前显示已有图片
- **名称排序** - 支持名称 A-Z / Z-A 和时间排序
- **时间排序缓存** - (2026-07-29) 文件夹 mtime 写入数据库，排序时无需文件 IO
- **名称搜索** - 导航栏搜索框实时按歌单名称模糊搜索，300ms 防抖
- **标签按钮** - (2026-07-29) 详情页标签以可点击的胶囊按钮显示，点击即可按标签过滤
- **联合筛选选择器** - (2026-09-01) 导航栏 `+` 按钮弹出三页签选择窗口（标签 / CV / 社团），每页独立搜索、整行点击勾选、多选，CV/社团条目附带作品数辅助挑选，已激活条件自动预勾选
- **社团/CV 点击筛选** - (2026-09-01) 详情页社团/CV 胶囊可点击，CV 多声优自动拆分为独立胶囊，点击即按该维度过滤
- **联合搜索** - (2026-09-01) 标签 / CV / 社团三维度叠加过滤：同维度内多选取「或」、维度之间取「与」；导航栏按维度前缀显示芯片，可逐个 × 移除
- **标签叠加** - (2026-07-29) 多次从详情页或选择器添加标签时自动叠加过滤；使用过滤时搜索框自动隐藏
- **标签管理** - 标签支持空格、逗号、换行分隔；可移除的标签带 × 按钮；刷新或翻页自动清除
- **分页浏览** - 每页 30 个歌单，底部翻页控件，翻页自动回顶
- **自然排序** - 曲目按文件名自然顺序排列（1, 2, 10 而非 1, 10, 2）
- **封面标签** - 支持 `封面.jpg` / `cover.jpg` 封面图片（本地封面优先于 DLsite 网络封面）
- **音频播放** - 内置播放器，支持播放、暂停、上一首、下一首
- **持续播放** - (2026-08-06) 播放队列与展示列表解耦，返回歌单列表/切换详情页时音乐不中断，当前曲目自动高亮
- **进度控制** - 可拖动/点击进度条跳转，显示当前/总时长
- **点击曲目名跳转** - 播放条左侧曲目名可点击，直接跳转到曲目所在文件夹的子歌单；返回键回到所属主歌单
- **音量调节** - 独立音量滑块（0-100%）
- **背景任务状态** - 扫描与信息拉取共用分页栏左侧的圆环百分比，不额外占用一行；状态短文字显示当前阶段，悬停查看完整进度，支持取消扫描与查看抓取日志
- **目录级指纹** - (2026-08-03) 扫描预检改用目录级指纹，只 stat 目录 mtime，unchanged 判断从十几秒降到 1-2 秒
- **静默扫描** - (2026-08-03) 进入程序时若目录无变化，扫描条不再出现，用户无感
- **曲目数批量更新** - (2026-08-04) 容器歌单聚合后单次批量写入 track_count，数百歌单更新从数秒降到毫秒级
- **扫描完成即时刷新** - (2026-08-04) "扫描完成"回调移至聚合与指纹重建之后，完成后 UI 立即刷新
- **复制歌单名称** - (2026-07-29) 右键歌单卡片或列表项可复制歌单名称到剪贴板
- **DLsite 信息自动抓取** - (2026-09-01) 从歌单名自动识别 RJ 码，后台 4 线程并行抓取 DLsite 作品信息（标题/社团/CV/发售日/分类/简介等），独立数据库 `data/dlsite.db` 存储，启动时批量校验已缓存 ID 只补缺失，绝不重复请求
- **DLsite 点击插队** - (2026-09-01) 点击尚未获取信息的歌单时优先抓取该歌单，详情页显示"正在获取"占位，完成后自动填充
- **DLsite 进度与日志** - 分页栏圆环实时显示抓取百分比，悬停查看已处理数、总数与当前任务；旁边的 `…` 按钮打开带时间戳的抓取日志窗口（成功/失败/跳过）
- **网络分类标签** - (2026-09-01) 歌单标签统一使用 DLsite 网络分类（替代本地 `标签.txt`，扫描器不再读写标签文件），详情页以可点击胶囊按钮展示，点击过滤；无网络数据的歌单自动清除残留本地标签
- **DLsite 封面** - (2026-09-01) 自动下载作品封面到 `data/dlsite_covers/`，本地无封面文件的歌单自动回填网络封面（本地封面优先），主列表与详情页同步显示
- **抓取防卡顿** - (2026-09-01) 信息同步采用单事务批量写库 + 按 RJ 码精准同步，详情页停留期间推迟列表刷新，返回时统一补刷，抓取全程 UI 流畅
- **RJ 码识别增强** - (2026-09-01) 兼容 RJ 码后紧跟汉字/横杠/空格的歌单名（如 `RJ01155419作品名`），不误匹配超长无效码
- **右键菜单美化** - (2026-09-01) 歌单卡片/列表项右键菜单采用主题样式，悬停时背景与文字颜色同时变化，清晰可读

## 安装

### 环境要求

- Python 3.10+（代码在运行时使用 `X | None` 注解，需 3.10 及以上）
- Windows 10+（PyQt6 / Qt 6 最低支持 Windows 10）

### 安装依赖

```bash
pip install -r requirements.txt
```

依赖清单：
- `PyQt6` - GUI 框架
- `Pillow` - 图像处理（生成缩略图）
- `curl_cffi` - DLsite 页面抓取（TLS 指纹模拟，可选，缺失时 DLsite 功能静默降级）
- `beautifulsoup4` - DLsite 页面解析（可选，同上）

## 使用

```bash
python src/main.py
```

### 流程概览

1. 启动程序，显示 **主启动器** 界面
2. 点击 **写真** 卡片，进入写真浏览模块（启动器自动隐藏）
3. 使用完毕，点击 **← 返回主界面** 或关闭窗口，回到启动器
4. 其余模块（动漫、视频）框架预留，点击提示"开发中"

### 写真模块首次使用

1. 点击左侧 **扫描** 按钮
2. 等待扫描完成（程序会遍历 `E:\hhh\写真` 目录并建立索引数据库）
3. 扫描完成后，左侧显示作者列表，右侧显示作品卡片

### 写真模块日常使用

- **浏览** - 点击左侧作者筛选作品，搜索框按作品名搜索
- **查看作品** - 点击作品卡片进入缩略图墙，显示该作品所有图片
- **查看图片** - 点击缩略图进入全屏查看器，←/→ 翻页，ESC 退出
- **返回** - 在缩略图墙界面，点击左侧其他作者自动返回并切换；或按 Esc / Backspace
- **回启动器** - 点击侧边栏底部 **← 返回主界面** 按钮

### 音频模块首次使用

1. 在启动器点击 **音频** 卡片进入
2. 首次使用点击 **设置** 配置音频根目录路径
3. 进入模块后等待自动后台扫描完成；也可点击 **扫描** 手动重扫
4. 主列表显示歌单分组，按 30 个/页分页

### 音频模块日常使用

- **浏览歌单** - 网格/列表双视图切换；多根目录的主歌单混合显示在同一个列表中
- **名称搜索** - 搜索框输入文字，实时模糊搜索歌单名称，支持清空；搜索时标签过滤自动清除
- **标签搜索** - 进入歌单详情页，点击标签胶囊按钮按该标签过滤歌单；使用过滤时搜索框自动隐藏
- **社团/CV 搜索** - 详情页点击社团/CV 胶囊即按该维度过滤；CV 多声优拆分为独立胶囊分别可点
- **联合筛选** - 导航栏 `+` 打开三页签选择器（标签/CV/社团），独立搜索、多选；同维多选「或」、跨维叠加「与」
- **移除筛选** - 导航栏激活的标签/社团/CV 芯片带 ×，点击 × 逐个移除；refresh 清除全部
- **排序** - 下拉框选择名称 A-Z / Z-A 或时间排序
- **翻页** - 底部上一页/下一页按钮，翻页自动回顶
- **查看歌单** - 点击主歌单卡片进入详情页，查看其封面、标签、本目录曲目与含音频的子歌单
- **类型筛选** - 详情页曲目列表右上角下拉框，按文件格式（MP3/FLAC/WAV 等）过滤曲目
- **子歌单** - 仅含音频的文件夹显示为子歌单，例如 `文件夹1 > 文件夹2 > 文件夹3`；点击后只显示该文件夹自己的曲目
- **后台状态** - 分页栏左侧圆环显示扫描或信息拉取百分比，悬停查看完整信息；`×` 取消扫描，`…` 查看抓取日志。进入详情页后仍可查看后台状态，任务结束后自动隐藏
- **播放** - 双击曲目或点击播放按钮开始播放
- **进度/音量** - 拖动进度条跳转，拖动音量滑块调节
- **播放设备** - 系统切换默认播放设备后程序自动跟随，无需重启
- **设置** - 修改音频根目录路径，删除数据库重新扫描

## 数据存储

所有数据统一存储在 `data/` 目录下：

- **SQLite 数据库** - `data/resource_manager.db`（写真模块）和 `data/audio_manager.db`（音频模块），WAL 模式 + 64MB cache
- **DLsite 缓存库** - `data/dlsite.db`（作品信息独立缓存）和 `data/dlsite_covers/`（封面图片，按 RJ 码命名）
- **作品缩略图** - `data/thumbnails/` 目录，每个作品首图生成 240px 缩略图
- **单图缩略图缓存** - `data/thumbnails/img/` 目录，按 `MD5(path)_WxH.jpg` 命名，仅 ≤512px 的缩略图写盘
- **扫描指纹缓存** - `data/.scan_fingerprint.json`，记录各资源目录指纹（写真模块和音频模块均使用目录级 mtime）

删除 `data/` 下的数据库文件和 `thumbnails/` 目录可清空索引与缓存；删除 `.scan_fingerprint.json` 可让下次扫描强制重新同步。

## 性能优化

- **指纹预检** - 扫描前生成目录指纹，无变化时跳过整个扫描流程，数万张图只需毫秒级
- **目录级指纹预检** - (2026-08-03) 写真模块和音频模块预检均改用目录级指纹（只 stat 目录 mtime，不 stat 文件），800+ 文件夹 unchanged 判断从十几秒降到 1-2 秒
- **自动扫描静默化** - (2026-08-03) 进入写真/音频模块时若目录无变化，扫描条不再出现，仅检测到真实变化才显示进度
- **增量扫描** - 通过 mtime 字段对比，仅同步变化的图片，扫描 20000+ 张仅需 0.3s
- **缩略图懒加载** - 仅加载可见区域内的卡片，视口检测触发
- **LRU 内存缓存** - OrderedDict 实现，64 像素对齐标准化键，避免窗口 resize 时缓存失效
- **磁盘缓存** - ≤512px 缩略图持久化，重启后免解码
- **异步解码** - QThreadPool + QRunnable，token 机制防止过期回调污染 UI
- **QListWidget IconMode** - 图片墙用 QListWidget + 自定义 ItemDelegate，替代 QFrame+QLabel，减少 widget 树开销
- **FastTransformation** - 缩略图使用快速缩放算法
- **布局冻结** - 切换作者时批量添加卡片，避免中间重排
- **滚动按行步进** - 滚动条 singleStep 设为单行卡片高度，避免一次跳过多行
- **数据库长连接** - 持久连接 + WAL 模式，避免反复 open/close
- **批量子歌单查询** - `get_child_counts_batch()` 一次查询替代 N 次逐个查询，翻页从 60+ 次降到 1 次
- **曲目计数优化** - 直接读取数据库 `track_count` 字段，避免拉取全量曲目仅为计数
- **按需视图渲染** - (2026-07-29) 翻页仅构建当前可见视图（网格/列表），切换时按需重建，翻页耗时减半
- **封面缩略图缓存** - 歌单卡片按显示尺寸解码封面并缓存，已有封面在首屏绘制前显示；已缓存的 DLsite 封面也在首屏列表创建前同步
- **时间排序缓存** - (2026-07-29) 文件夹 mtime 写入数据库，排序时零文件 IO，旧数据库惰性迁移
- **递归CTE优化** - (2026-07-29) 后代歌单/曲目/封面查询改用递归CTE，500+子歌单从150+次查询降为3次
- **批量删除重构** - `delete_playlist` 用递归 CTE 删除歌单及子歌单，并显式清理关联曲目
- **临时表方案** - (2026-07-29) list_tracks_by_playlist_ids / delete_tracks_not_in 改用临时表，突破SQLite 999参数上限
- **track_count 批量更新** - (2026-08-04) 容器歌单聚合后一次 `executemany` 批量写，替代逐条短连接更新，数百歌单从数秒降到毫秒级
- **扫描完成回调后置** - (2026-08-04) "扫描完成"进度回调移到聚合 + 指纹重建之后，UI 收到信号即刷新，不再延迟
- **首次扫描提速** - (2026-08-18) 4 项优化叠加：指纹复用避免第三次目录遍历、传递已收集文件列表消除冗余 listdir、QMediaPlayer 延迟初始化、多根目录并行指纹预检，首次打开从 8-9 秒降至 2-3 秒

## 资源目录结构要求

写真模块期望以下目录结构：

```
E:\hhh\写真\
├── 作者名1\
│   ├── 作品名1\
│   │   ├── 001.jpg
│   │   ├── 002.jpg
│   │   └── ...
│   └── 作品名2\
│       └── ...
├── 作者名2\
│   └── ...
└── ...
```

音频模块期望以下目录结构（支持多层级嵌套，可配置多个根目录）：

```
E:\音频\
├── 歌单1\                      # 直接包含音频 → 普通歌单
│   ├── 封面.jpg                # 可选本地封面（优先于 DLsite 网络封面）
│   ├── 01-歌曲.mp3
│   └── 02-歌曲.flac
├── RJ01675439-作品名\          # 歌单名含 RJ 码 → 自动抓取 DLsite 信息/分类/封面
│   ├── 01-音声.mp3
│   └── 02-音声.wav
├── 歌手A\                      # 无直接音频，有子文件夹 → 容器歌单
│   ├── 封面.jpg                # 可选封面
│   ├── 专辑1\
│   │   ├── 01-歌曲.mp3
│   │   └── 02-歌曲.wav
│   └── 专辑2\
│       └── ...
└── 合集\                       # 有音频 + 子文件夹 → 普通歌单 + 子歌单
    ├── 封面.jpg
    ├── 独立曲目.mp3
    └── 子专题\
        └── ...
```

多个根目录时，各根目录的主歌单混合显示在同一个列表中。打开主歌单后，只有含音频的子文件夹单独列出；例如 `歌手A > 专辑1`。升级到 v1.6.0 后，音频模块会自动完整扫描一次，以清理旧版可能残留的空歌单或曲目，此后恢复指纹增量扫描。

> 注：标签不再使用本地 `标签.txt` 文件，统一来自 DLsite 网络分类（歌单名含 RJ 码时自动抓取）。

## 架构设计

按模块与职责拆分，单个文件控制在 ~600 行以内，便于维护：

- **写真模块 UI** - `main_window.py`（主窗口）+ `photo_theme.py`（主题样式）+ `photo_widgets.py`（设置对话框、扫描线程）
- **音频模块 UI** - `audio_view.py`（主窗口：页面组装、播放器控制、扫描）+ `audio_browser.py`（主歌单浏览器：搜索/标签/双视图/分页）+ `audio_detail.py`（歌单详情页）+ `audio_widgets.py`（卡片、设置对话框）+ `audio_player.py`（底部播放条控件）+ `audio_threads.py`（后台线程）+ `audio_theme.py`（主题与工具）
- **UI 组件分层** - 各模块通过信号（pyqtSignal）解耦：播放条只发控制信号，浏览器只发 `openPlaylist`，详情页只发 `backClicked`/`trackDoubleClicked` 等，主窗口统一连接
- **后端与前端分离** - `resource_manager/`（写真）与 `audio_manager/`（音频）负责数据库与扫描，UI 层不直接操作 SQLite
- **设计令牌单一来源** - `ui/theme_base.py` 集中定义全项目配色常量，各模块主题与启动器统一引用，杜绝重复声明

## 模块扩展

程序采用多模块架构，在 [src/ui/launcher.py](src/ui/launcher.py) 中定义模块列表（`MODULES` 常量），新增模块只需：

1. 在 `MODULES` 列表中添加模块定义（id、图标、标题、描述、状态）
2. 状态设为 `"ready"` 表示已就绪，`"coming_soon"` 表示开发中
3. 在 `_open_module()` 中处理新模块的打开逻辑
